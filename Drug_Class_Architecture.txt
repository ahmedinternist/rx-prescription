DRUG CLASS ARCHITECTURE
=======================

Purpose
-------
This file documents the therapeutic classification used by the application and
shows a recommended subgroup layer for clearer navigation.

Recommended hierarchy
---------------------
Major therapeutic group
  -> Subgroup
     -> Detailed drug class
        -> Mapped medicines

Current implementation note
---------------------------
The application currently stores:
  1. therapeutic_group = major therapeutic group code
  2. detailed_class    = detailed drug class name
  3. class_mappings    = multiple mappings in this form:
                         group_code::detailed_class|group_code::detailed_class

The subgroup headings below are an organizational recommendation. They are not
currently stored as a separate database field. The existing category field is a
local/favorite tag and should not be treated as a clinical subgroup.

DATABASE IMPLEMENTATION OPTION
==============================

To implement the recommended third level later, add an optional column:

  subgroup

Recommended database columns:

  brand_name
  generic_name
  strength
  form
  therapeutic_group
  subgroup
  detailed_class
  class_mappings
  mapping_status
  notes

Rules:
  - A major therapeutic group contains one or more subgroups.
  - A subgroup contains one or more detailed drug classes.
  - A detailed drug class contains mapped medicines.
  - One medicine may belong to multiple detailed classes.
  - Existing two-level mappings must continue to work when subgroup is empty.
  - Subgroups are for organization and navigation, not prescribing advice.
